# Internationalisation

Status: implemented
Owner: Lead / content
Related: [decision 0002](../decisions/0002-next-intl-three-locales.md) | [decision 0003](../decisions/0003-message-catalogs-as-content.md) | [translation notes](../content/translation-notes.md)

## Problem

Belarusian businesses and international clients must be able to read the entire site in Russian, Belarusian or English without losing navigation context or SEO value.

## Behaviour

1. Locales are `ru` (default), `be`, `en`. Routing uses `localePrefix: 'always'`; `/` redirects to `/ru`.
2. Switching the language keeps the current pathname (`/be/privacy` → `/en/privacy`).
3. Language choice is stored in the URL only — no locale cookie, no consent banner needed.
4. Every message catalogue has the same structure, array lengths, numeric values and ICU placeholders; `pnpm check:i18n` enforces it.
5. Brand names are localized: «Цифровая Беларусь» (ru), «Цыфровая Беларусь» (be), "Digital Belarus" (en). Product and technology names stay untranslated.
6. `<html lang>` matches the active locale.
7. Every page emits canonical, `hreflang` alternates (all three locales), localized title/description and an Open Graph image per locale.
8. The sitemap lists all localized pages with `alternates.languages`; `robots.txt` points to it.
9. Number, currency and plural formatting are locale-aware (`Intl` APIs; `{days, plural, …}` in the calculator).
10. Belarusian text uses proper `ў`, `і`, `ё` and the typographic apostrophe; fonts include the needed Cyrillic subsets.

## Acceptance criteria

- [x] All locales expose identical message keys.
- [x] Switching locale does not reset scroll position or change the route.
- [x] No untranslated Russian strings remain in `be`/`en` except documented technical names.
- [x] Canonical and `hreflang` URLs are absolute and self-referential.
- [x] ICU plural works for 1/2/5 days in Belarusian and Russian.
- [x] No cookie is set by the locale switcher.

## Out of scope

- Automatic geolocation-based locale detection.
- RTL languages.
- User-generated translations or a CMS.

## Verification

`pnpm check:i18n`, `pnpm build` (all locales pre-rendered), manual review of `messages/*.json`, `curl -I` checks of `hreflang` and canonical tags.
